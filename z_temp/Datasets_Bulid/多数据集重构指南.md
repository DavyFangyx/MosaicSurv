# SurvPGC 多数据集重构指南

## 1. 重构目标

将当前以 `KICH / KIRC / KIRP` 为主的数据准备与训练流程，扩展为统一支持以下 9 个数据集：

```text
tcga_brca
tcga_coad
tcga_kich
tcga_kirc
tcga_kirp
tcga_lihc
tcga_prad
tcga_read
tcga_stad
```

重构重点：

- 统一数据集命名
- 统一 metadata、clinical、RNA、split 输出规则
- 适配按数据集隔离的 `SurvPGC_Workspace`
- 保留不同 TCGA 文件树的特殊处理能力
- 清理 KICH/KIRC/KIRP 硬编码
- 让训练、批量实验、结果分析使用同一套数据集配置

## 3. Workspace 最终约定

当前 Workspace 结构已经确定为“按数据集隔离”：

```text
SurvPGC_Workspace/
├── build_workspace.sh
├── convert_wsi_h5_to_pt.py
├── Readme.md
├── _cache/
│   └── wsi_pt/
│       └── uni_v1/
├── tcga_brca/
│   ├── P/uni_v1/
│   ├── C/L0/
│   ├── C/L1/
│   ├── C/L2/
│   ├── C/L3/
│   ├── C/L4/
│   ├── C/L5/
│   └── G/
│       ├── scFoundation_embedding_cell_norm/
│       ├── scFoundation_embedding_cell_raw/
│       ├── scFoundation_embedding_gene_norm/
│       └── scFoundation_embedding_gene_raw/
├── tcga_coad/
├── tcga_kich/
├── tcga_kirc/
├── tcga_kirp/
├── tcga_lihc/
├── tcga_prad/
├── tcga_read/
└── tcga_stad/
```

训练时的路径必须按 `study` 拼接：

```text
SurvPGC_Workspace/<study>/P/uni_v1
SurvPGC_Workspace/<study>/C/<clinic_embedding>
SurvPGC_Workspace/<study>/G/<gene_embedding>
```

示例：

```bash
--data_root_dir SurvPGC_Workspace/tcga_coad/P/uni_v1
--clinic_dir SurvPGC_Workspace/tcga_coad/C/L4
--gene_dir SurvPGC_Workspace/tcga_coad/G/scFoundation_embedding_gene_raw
```

### Workspace 行为要求

- `P`：按完整 `slide_id` 对应的 `.pt` 文件读取
- `C`：按患者级 `case_id` 读取
- `G`：按患者级 gene 特征读取
- WSI 源目录只有 `.h5` 时，先转换到 `_cache/wsi_pt/uni_v1/`
- `tcga_kich`、`tcga_kirc`、`tcga_kirp` 可以共享同一个 WSI 源目录，但最终必须分别挂载到对应 Workspace 目录
- Clinic 或 Gene 源不存在时，仍可创建空目录，但训练前必须明确检查该模态是否可用

## 4. 数据集配置原则

### 4.1 registry 的职责

`dataset_deployment/registry.yaml` 只负责统一索引和标准路径，不负责描述所有原始文件树细节。

建议字段：

```yaml
version: 1

datasets:
  tcga_coad:
    display_name: TCGA-COAD
    deployment_doc: datasets/tcga_coad.md
    stats_dir: data_tcgal_stats/TCGA-COAD
    metadata_csv: datasets_csv/metadata/tcga_coad.csv
    clinical_csv: datasets_csv/clinical_data/tcga_coad_clinical.csv
    rna_dir: datasets_csv/raw_rna_data/combine/coad
    split_dir: splits/5foldcv/tcga_coad
    workspace_root: SurvPGC_Workspace/tcga_coad
    enabled: true
```

9 个数据集都应登记，`tcga_stad` 不再作为跳过数据集。

### 4.2 部署文档的职责

每个 `dataset_deployment/datasets/tcga_<study>.md` 都必须记录：

- 原始数据根目录
- Clinic、Gene、WSI 的实际路径
- 文件树差异
- clinical JSON 位置
- sample sheet、manifest、metadata 的位置
- 患者 ID 映射规则
- Gene 文件名映射规则
- WSI 文件名映射规则
- 当前可用模态
- 特殊异常与跳过条件
- 生成命令
- 验证命令

由于不同数据集的文件树不同，不能要求所有数据集完全复用同一套扫描逻辑。推荐做法是：

```text
registry.yaml
    负责找到数据集

tcga_<study>.md
    负责解释数据集如何部署

generate_requirements/
    负责执行通用流程和数据集适配逻辑
```

## 5. 文件命名与映射规则

### 5.1 study 命名

训练侧统一使用小写 slug：

```text
tcga_brca
tcga_coad
tcga_kich
tcga_kirc
tcga_kirp
tcga_lihc
tcga_prad
tcga_read
tcga_stad
```

源数据名称可以保留：

```text
TCGA-BRCA
TCGA-COAD
TCGA_LIHC
TCGA-KICH-KIRC-KIRP
```

但源名称只能存在于 registry 或数据集部署文档中，不能散落在训练代码里。

### 5.2 Gene 文件命名

当前 Gene 源文件可能类似：

```text
TCGA_LIHC__0cb37227-b328-4083-8c3c-fb8a850fc5bf.pt
```

而训练代码通常按：

```text
TCGA-XX-XXXX.pt
```

读取。因此必须新增：

```text
datasets_csv/feature_manifests/tcga_<study>.csv
```

建议字段：

```text
case_id,source_file,workspace_file,modality,embedding
TCGA-BC-A217,TCGA_LIHC__0cb37227-....pt,TCGA-BC-A217.pt,gene,scFoundation_embedding_cell_norm
```

推荐方案：

- 不修改原始源文件
- Workspace 中建立标准化软链接
- 训练代码只读取标准化后的 `workspace_file`
- manifest 保存源文件与标准文件的对应关系

### 5.3 WSI 文件命名

metadata 中的：

```text
slide_id = TCGA-XX-XXXX-01Z-00-DX1.xxx.svs
```

Workspace 中应存在：

```text
TCGA-XX-XXXX-01Z-00-DX1.xxx.pt
```

即只去掉 `.svs`，不改变其他部分。

## 6. 数据生成流程

每个数据集的标准生成顺序：

```text
原始数据 / data_tcgal_stats
        ↓
患者级模态映射
        ↓
metadata CSV
clinical CSV
rna_clean.csv
feature manifest
        ↓
5-fold split
        ↓
Workspace 特征校验
        ↓
训练
```

推荐命令接口：

```bash
python generate_requirements/generate_metadata_csv.py --study tcga_coad
python generate_requirements/generate_clinical_csv.py --study tcga_coad
python generate_requirements/generate_rna_clean_csv.py --study tcga_coad
python generate_requirements/generate_5fold_splits.py --study tcga_coad
```

批量执行：

```bash
python generate_requirements/generate_dataset.py --all
```

生成脚本应支持：

- `--study <study>`
- `--all`
- `--dry-run`
- `--validate-only`

## 7. 训练入口改造

`main.py`、`utils/process_args.py` 和 `run.sh` 的路径应从：

```text
固定的 SurvPGC_Workspace/P
固定的 SurvPGC_Workspace/C
固定的 SurvPGC_Workspace/G
```

改为：

```text
SurvPGC_Workspace/<study>/P
SurvPGC_Workspace/<study>/C
SurvPGC_Workspace/<study>/G
```

默认推导关系：

```text
study = tcga_coad

label_file = datasets_csv/metadata/tcga_coad.csv
clinical_file = datasets_csv/clinical_data/tcga_coad_clinical.csv
omics_dir = datasets_csv/raw_rna_data/combine/coad
split_dir = splits/5foldcv/tcga_coad
data_root_dir = SurvPGC_Workspace/tcga_coad/P/uni_v1
clinic_dir = SurvPGC_Workspace/tcga_coad/C/L4
gene_dir = SurvPGC_Workspace/tcga_coad/G/scFoundation_embedding_gene_raw
```

训练开始前必须检查：

- metadata 是否存在
- clinical CSV 是否存在
- `rna_clean.csv` 是否存在
- split 文件是否完整
- WSI、Clinic、Gene 特征文件是否能按 metadata 找到
- 特征 tensor shape 是否正确

## 9. 验收标准

### 单数据集验收

以 `tcga_coad` 为例：

```bash
python generate_requirements/generate_dataset.py --study tcga_coad --validate-only
```

应确认：

- metadata、clinical、RNA 文件存在
- split 文件存在
- Workspace 路径存在
- metadata 中的 case/slide 均能找到对应特征
- Gene manifest 中的源文件和 Workspace 文件一一对应

### 全数据集验收

9 个数据集都应能完成：

```text
metadata
clinical
rna_clean
feature_manifest
5-fold split
Workspace 校验
```

### 新增数据集验收

后续新增数据集时，原则上只需要：

1. 增加 `data_tcgal_stats/<dataset>/`
2. 增加 `dataset_deployment/datasets/tcga_<study>.md`
3. 在 `registry.yaml` 中登记
4. 实现必要的数据集适配规则
5. 运行生成、挂载和校验流程

不应修改模型主体和训练循环。

## 10. 最终设计原则

```text
registry.yaml
    负责“有哪些数据集、标准输出在哪里”

dataset_deployment/datasets/*.md
    负责“这个数据集的原始文件树和特殊规则是什么”

data_tcgal_stats/
    负责“患者和模态可用性统计是什么”

datasets_csv/
    负责“训练标签、临床表、RNA 表和映射表”

SurvPGC_Workspace/tcga_<study>/
    负责“训练实际读取的三模态特征”

splits/
    负责“训练划分”
```

核心原则是：**统一标准输出，不强行统一原始数据树；统一训练接口，不强行删除数据集差异。**
