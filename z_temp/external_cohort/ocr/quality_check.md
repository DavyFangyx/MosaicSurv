## 2. 字段级 OCR 可靠性

### 2.1 可靠（可直接用，抽查 0 错）

| 字段 | 证据 |
|------|------|
| `pathology_id`（病理号） | 抽查 15 份，逐字符一致；格式为 `D23xxxxx`/`23xxxxx`/`22xxxxx`/`21xxxxx` |
| `age`（年龄） | 抽查全部一致；范围 46–78 岁 |
| `sex`（性别） | 抽查一致（含 090023 反直觉的"女"，原图确认无误） |
| `collect_date`（送检日期） | 抽查一致，30/30 齐全，格式统一 `YYYY-MM-DD` |
| `report_date`（报告日期） | 抽查一致；仅末尾时间戳（如 `11:0.`）被截断，不影响日期 |
| `organ`（器官） | 由"送检标本/送检材料 + 肉眼所见"判定，30/30 无歧义 |
| `cancer_type`（癌种） | 30/30 明确：肺腺癌 10、肾透明细胞癌 10、肝细胞癌 10 |
| `tumor_size_cm` | 直接从"肉眼所见/病理诊断"的数字串提取，抽查一致 |
| `clinical_diagnosis` | **有值**的 19 份抽查一致（另有 11 份原报告该栏本就为空） |

### 2.2 中等可靠（需规范/复核）

| 字段 | 风险 |
|------|------|
| `ihc_summary` | **项目名基本可靠**，符号易错：括号丢失、`+/-` 粘连、连字符丢失、大小写不规范（`Ck7`、`PaX-8`）；**整段吞字**确有发生（090113 的 `CD34(内皮细胞+)` 被吞） |
| `grade`（分级/分化） | 罗马数字偶被替换成阿拉伯数字（`2级`）；错字（`Edmondson-Sttiner`）；3 份肺报告原文本就没写分化程度 |
| `mvi` | 全部写作 `MO`，**字母 O 与数字 0 字形不可辨**；按 M0/M1/M2 体系取 M0（10/10 全阴，无阳性例） |
| `ki67_pct` | 数值抽查与图一致；但**只在 11/30 存在**，且 8/11 带"约"字（目测估计） |

### 2.3 不可靠（必须人工复核）

| 字段 | 典型错误 |
|------|----------|
| `ptnm` | **数字/字母混淆**：`pT1bN0Mx` → OCR `pTIbNOMx`（1→I, 0→O）。同类错误在 5 份有分期的报告中出现 5/5 |
| `lymph_node_status` | **最脆弱字段**。括号内分数会被拆散、错位、变成乱码：
  - `(0/1)` → `(o/i6`
  - `(0/1)` → `do/ip`（完全乱码）
  - `(0/i)`
  - 多列排版时，8 个分数与 10 个组号被拆成两段、顺序全乱（2301595）
| 整行/整段 | 确有**整行丢失**：2108531 的 `病理诊断` 行在 OCR 中完全不存在；2213740 诊断第 2 条被从中间截断；多份报告的 `肉眼所见` 后半段丢失 |

### 2.4 一句话结论

> **报告的"标签型"字段（病理号/年龄/性别/日期/器官/癌种/大小）OCR 可靠；
> "结论型"字段（pTNM、淋巴结分数、IHC 符号）OCR 不可靠，必须回原图核对。**

规律：**OCR 在"字母数字混排的短符号串"（`pT1bN0Mx`、`(0/1)`、`(内皮细胞+)`）上系统性失败**，在连续中文上表现良好。

## 3. 对后续使用 C 模态（临床模态）的建议

### 3.1 可直接使用（低风险，无需复核）

`pathology_id`（作 case_id）、`organ`、`cancer_type`、`age`、`sex`、`collect_date`、`report_date`、`tumor_size_cm`、`clinical_diagnosis`（有值的 19 例）。

### 3.2 必须人工复核后才能进入模型

`ptnm`、`stage_mapped`、`lymph_node_status`、`ihc_summary`、`ki67_pct`、`mvi`。

- `lymph_node_status`：本队列 11 例有淋巴结，**建议全部 11 例回原图核对分子/分母**（抽查 2 例，2 例都有错）。
- `ptnm`：5 例有分期，**5/5 都有字符级错误**（虽已按原图修正）。

### 3.3 可用于建模的字段盘点（30 例）

| 字段 | 可用量 | 说明 |
|------|--------|------|
| organ / cancer_type | 30/30 | 三器官各 10 例，均衡 |
| age / sex | 30/30 | — |
| tumor_size_cm | 30/30 | 连续变量 |
| lymph_node_status | 11/30 | 全部为 N0；**本队列无淋巴结阳性病例** → N 分期无区分度 |
| grade | 20/30 | 肾 10 例全缺（无 ISUP 分级）；肺缺 3；肝齐 |
| ki67_pct | 11/30 | 仅肝（10）+ 肺（1） |
| mvi | 10/30 | 仅肝，且全为 M0 → 无区分度 |
| pTNM / stage | 5/30 | 仅 2023 年肺报告有；其余 25 例缺失 |

### 3.4 建模建议

1. **本队列规模（n=30）与标签缺失率不支持训练**，建议定位为**外部验证/演示队列**，或用于检验 C 模态对"跨中心分布偏移"的鲁棒性。
2. **不要用 `stage_mapped` 作主标签**：83% 缺失，且现有的 5 例建立在 `Mx≈M0` 假设之上。
3. 可用的**弱标签组合**优先考虑：`organ + grade + tumor_size_cm + N状态(二值:均阴性)`；Ki67/MVI 因无区分度（全阴/没有）不宜作监督信号，但可作为**缺失模态实验**的对象。
4. **器官间不要混建一个分类头**：肝(HCC)/肾(ccRCC)/肺(LUAD) 的 grade 体系、IHC panel、预后驱动因素都不同，建议按器官分层或加 organ embedding。
5. 本队列**无任何随访/生存信息**（报告只有送检/报告日期）→ **不能直接用于生存预测**；若目标是生存任务，必须另行获取随访数据。
6. C 模态输入若是"结构化表格"，缺失值需显式编码为 NaN + 缺失指示位，不要填 0 或均值（缺失本身有信息：肾不做分级、肝不做淋巴结清扫）。

## 4. 与项目 `datasets_csv/clinical_data/` 的格式对齐

### 4.1 目标格式

项目现有临床表（例：`tcga_lihc_clinical.csv`、`tcga_kirc_clinical.csv`）格式为：

```
,case_id,stage,subtype,grade
0,TCGA-2V-A95S,II,LIHC,G3
```

- `stage`：罗马数字，含 A/B/C 细分（实测取值 `I, II, III, IIIA, IIIB, IIIC, IV, IVB, N/A`）
- `subtype`：TCGA 项目码（`LIHC`、`KIRC`…）
- `grade`：`G1–G4`

### 4.2 对齐规则

| 本表字段 | 对齐到 | 规则 |
|----------|--------|------|
| `pathology_id` | `case_id` | 建议加前缀防冲突，如 `EXT-D2301220`（病理号是可保留的伪标识） |
| `organ` / `cancer_type` | `subtype` | liver+HCC → `LIHC`；kidney+ccRCC → `KIRC`（或 `KIRP`/`KICH` 需按亚型改）；lung → **项目当前无 LUAD 表**，需新建 `tcga_luad_clinical.csv` 或另立目录 |
| `stage_mapped` / `stage_simple` | `stage` | 见 4.3 |
| `grade_tcga` | `grade` | 见 4.4 |

### 4.3 `stage` 映射（AJCC）

本队列报告采用 **AJCC 第 8 版**肺分期（证据：2cm 结节记 `pT1b`、2.4cm 记 `pT1c`、同叶双结节记 `pT3`，均符合第 8 版口径）。

**肺癌 AJCC 8th 成组规则（本次使用的映射规则）**：

| T | N0 M0 | 说明 |
|---|-------|------|
| T1a（≤1cm） | IA1 | |
| T1b（>1–2cm） | IA2 | |
| T1c（>2–3cm） | IA3 | |
| T2a（>3–4cm，或脏层胸膜侵犯/主支气管受累/肺不张） | IB | |
| T2b（>4–5cm） | IIA | |
| T3（>5–7cm，或同叶独立结节，或胸壁/膈神经/心包受累） | IIB | |
| T4（>7cm，或纵隔/心脏/大血管/隆突/椎体/膈肌受累，或同侧不同叶结节） | IIIA | |
| N1 | — | T1–2N1M0=IIB；T3–4N1M0=IIIA |
| N2 | — | T1–3N2M0=IIIA；T4N2M0=IIIB |
| N3 / M1 | — | IIIB–IIIC / IVA–IVB |

**关键假设（务必记录在案）**：5 例有分期的报告 M 均为 `Mx`，映射时按 **Mx≈M0** 处理（根治性切除队列的常用假设）。若后续拿到影像或随访确认 M1，分期需整体重算。

**本队列 stage 结果（5/30）**：

| 病理号 | pTNM | stage_mapped (AJCC 8th) | stage_simple → 项目 `stage` |
|--------|------|--------------------------|------------------------------|
| D2301220 | pT1bN0Mx | IA2 | `I` |
| 2302089 | pT1bN0Mx | IA2 | `I` |
| 2301595 | pT1cN0Mx | IA3 | `I` |
| 2301451 | pT3N0Mx | IIB | `IIB` |
| 2300585 | pT1N0Mx | IA（亚级不可判） | `I` |

> 项目 `stage` 列没有 `IA1/IA2/IA3` 这一层细分，故 `IA2/IA3/IA` 一律降级为 `I`；`IIB` 可直接对上。
> 25 例无 pTNM 者 `stage` 必须留空（**不要**用 N/A 冒充，`N/A` 在项目表中表示"缺失"语义，可用，但需与本队列 25 例的"原报告无分期"区分标注）。

### 4.4 `grade` 映射

| 本表来源 | 项目 `grade` | 备注 |
|----------|--------------|------|
| 肺：高分化 / 中分化 / 低分化 | G1 / G2 / G3 | 形态学分化程度，与 TCGA-LUAD 的 grade 口径一致，属可靠近似 |
| 肝：Edmondson-Steiner Ⅱ / Ⅲ 级 | G2 / G3 | **TCGA-LIHC 的 grade 本身就是 Edmondson-Steiner 体系**（G1–G4 对应 ES Ⅰ–Ⅳ），可**直接对齐**，无需近似 |
| 肾：无 | **留空** | 报告未做 Fuhrman/ISUP 核分级；TCGA-KIRC 的 grade 为 G1–G4，**本队列 10/10 无法对齐**，须回原始病案补 |

### 4.5 落到项目格式后的样子（示例，供对接时参考）

```
# 肝（对 LIHC 表）
,case_id,stage,subtype,grade
0,EXT-2102850,,LIHC,G2        # 无 pTNM，stage 留空
1,EXT-2103645,,LIHC,G3
2,EXT-2104427,,LIHC,G2

# 肾（对 KIRC 表）
,case_id,stage,subtype,grade
0,EXT-D2302521,,KIRC,         # 无 pTNM、无核分级，双缺
1,EXT-D2301815,,KIRC,

# 肺（项目现无 LUAD 表，需新建）
,case_id,stage,subtype,grade
0,EXT-D2301220,I,LUAD,G2      # pT1bN0Mx, IA2 → I
1,EXT-2301451,IIB,LUAD,G2     # pT3N0Mx, IIB
2,EXT-2301282,,LUAD,G2        # 无 pTNM，stage 留空
```

### 4.6 需要新增的列（若 C 模态要用）

项目的 `clinical_data` 表**没有** Ki67、MVI、淋巴结状态、肿瘤大小这些列。本队列独有且对预后有意义的变量（`ki67_pct`、`mvi`、`lymph_node_status`、`tumor_size_cm`）需要：
- 方案 A：扩展临床表结构（新列，缺失填 NaN）；
- 方案 B：另建一张 `external_<organ>_pathology.csv`，以 `pathology_id` 与主临床表 JOIN。

推荐方案 B，避免污染主表结构（主表被现有训练/评估脚本按固定列读取）。
