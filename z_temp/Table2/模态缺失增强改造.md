# 模态缺失增强改造 — 实现文档

本文档是《三模态 PoE-VAE 生存预测模型 — 设计说明》的增量修订，覆盖两块改造：

1. **掩码语义修正**：dataloader 给出的模拟缺失只进 PoE，不进重建损失
2. **六个独立模型**：B/C × single/multi/film，其中 B+single 走冻结 enc/dec 后的缺失回填二次编码

本文档只定义实现规格，不改代码。未提及的部分一律沿用原设计说明。

原文档 §1–§5 的 Encoder / MIL Resampler / PoE / 重参数化 / Decoder 结构默认不变；**唯一例外是 B+single**：该分支 stage1 的 WSI 重建目标改为 `wsi_tokens (B, K, 768)`，不再使用原文档 §2.3 的独立池化头。本文档改写原文档的 §6.1（重建损失的掩码语义）、§7（模态缺失来源）、§8（训练流程），并新增读出层与回填设计。

## 0. 符号与索引约定

模态索引全局统一为 `[wsi, gene, clinic]`，与 `--alphapgc pathology,gene,clinic` 顺序一致。

Pattern 用 3-bit 表示，`bit0 = wsi, bit1 = gene, bit2 = clinic`：

| pattern_id | 二进制 | 可用模态 | 内部简称 | 现有 eval 标签 |
|---|---|---|---|---|
| 1 | 001 | wsi | P | P |
| 2 | 010 | gene | G | G |
| 3 | 011 | wsi, gene | PG | PG |
| 4 | 100 | clinic | C | C |
| 5 | 101 | wsi, clinic | PC | PC |
| 6 | 110 | gene, clinic | GC | CG |
| 7 | 111 | wsi, gene, clinic | PGC | PCG |

`pattern_id = 0` 不存在（至少保留一个模态）。全文用 `S` 表示一个 pattern，`PATTERNS = [1..7]`。训练日志和 checkpoint 选择用内部简称 `PGC` / `GC`；接到现有 `--eval_modalities` / Table2 输出时，全模态标签仍写 `PCG`，gene+clinic 仍写 `CG`。

当前实验 splits 三模态完整，没有真实 `.pt` 缺失。`avail` 只表示模拟缺失。文件不存在仍按现有 loader 失败处理，不另做文件级 mask。

## 1. 掩码语义修正（改写原文档 §6.1 / §7）

### 1.1 单掩码，重建不看它

原实现中 `ReconstructionLoss` 与 `GeneralizedPoE` 共用同一个 `available_mask`，被模拟缺失的模态既不进 PoE，也不进 `L_rec`。

当前实验 splits 是 complete-split：每个样本的 wsi / gene / clinic tensor 都在。在主模型中 dataloader 的 `avail` 只表示模拟缺失，不表示文件缺失。因此：

| 字段 | 形状 | 语义 | 消费方 |
|---|---|---|---|
| `avail` | `(B, 3)` bool | 该模态是否送入 PoE | `GeneralizedPoE`、生存读出 / refill |
| 重建目标 | 始终三模态齐全 | 不看 `avail` | `ReconstructionLoss` |

`avail` 的接口、来源、`selected_modalities` AND 规则全部保持现状。被 drop 的模态：tensor 仍完整给出，Encoder / Decoder 仍跑，只是 PoE 不用它。`L_rec` 始终对三个模态的真实目标计算。

生存评估仍用 `avail` / `eval_modalities`，不给重建打分。文件不存在仍按现有 loader 失败，本轮不为真实缺失另做 mask。

不变式：

```
avail.sum(dim=1) >= 1          # 每个样本至少保留一个输入模态（目前应该已经实现）
三个模态 tensor 始终存在       # complete-split
```

### 1.2 缺失来源（改写原文档 §7）

缺失只来自现有 dataloader 协议：

- `model_gen`：`utils/missing_mask_protocol.py` 里现有的 `modality_dropout()` / `model_gen_case_avail()`
- `unified_mask_csv`：固定 csv mask

`models/model_utils.py` 里的 `modality_dropout()` 当前没有调用点，保持未使用，不要重新接到 `SurvTriPoEVAE.forward()`。`forward()` 继续把 dataloader `avail` 当作 PoE 的 `available_mask`，不要再构造第二套重建 mask。

`selected_modalities` 规则保持现状：`_build_survtri_poe_vae_avail()` 把它 AND 到 dataloader `avail` 上，结果只给 PoE / 生存读出使用。

六个新 `--modality` 名字必须加入 `utils/missing_mask_protocol.py` 的 `POE_TRAIN_MODALITIES`，否则 `model_gen` 训练期不会模拟缺失。

`--eval_modalities` 仍是独立的 test-time 7-subset 开关，不改训练期 csv / dropout。

### 1.3 前向流程（除 B+single 外的默认路径）

```
1. avail = dataloader avail（再经 selected_modalities）
2. 三路 Encoder 全部前向 → (mu_i, logvar_i)
   WSI 默认路径仍用 §2.3 池化头从 wsi_tokens 产生 wsi_target
3. mu_joint, logvar_joint = GeneralizedPoE(mu, logvar, avail)
4. z = reparameterize(mu_joint, logvar_joint)      # 训练采样，推理取 mu_joint
5. 三路 Decoder 从 z 全部解码，不受 avail 影响
6. L_rec = ReconstructionLoss(recon_dict, target_dict)   # 不看 avail
7. J = JeffreysDivergence(mu_joint, logvar_joint)  # 不变
```

和第 2 步原实现的差别：`avail` 只在 PoE 处生效，不再用于跳过 Encoder，也不再挡住重建目标。Dataset / collate 对被 drop 的模态不得清零或置 None；tensor 仍要完整给出。complete-split 保证三个目标都在，所以不必再传一套全 1 mask。

`--modality survtri_poe_vae` 的现有 B/C 命令继承这一修正。B+single 的 WSI 重建目标见 §4.1，不走这一默认池化头。

### 1.4 `ReconstructionLoss` 修改（原文档 §6.1）

损失形式保持现有实现，不改公式：

```
L_rec_m = mean_elementwise_MSE_m / (2 * σ²_m) + (1 / 2) * log(σ²_m)
L_rec   = Σ_m L_rec_m
```

只改“重建不看 avail”、空 batch 日志，以及 MSE 的 flatten：

- `forward(recon_dict, target_dict, available_mask=None)`：complete-split 上 **忽略** `available_mask`，三个模态都进 `L_rec`。为兼容现有调用，mask 参数可保留，但调用方不要再把模拟缺失的 `avail` 传进去挡重建。推荐内部直接对全部样本算，等价于不再消费 mask
- 现有 `F.mse_loss(..., reduction="none").mean(dim=1)` 只对 2D 安全。B+single 的 WSI 会变成 `(B, K, 768)` 或 `(B, K*768)`，必须先 `reshape(B, -1)` 再对特征维取 mean。默认路径的 `(B, 768)` / `(B, 4*768)` / `(B, n_c*512)` 行为不变
- 若某个模态 count 仍为 0（防御性，complete-split 不应发生），该项不进入 `losses["total"]` 和 epoch 平均。返回 `recon.new_tensor(float("nan"))`，不要 Python `float("nan")`，也不要再写 `recon.sum() * 0.0`。现有 `_get_poe_step_metrics()` 对 `loss/rec_*` 调 `.item()`，必须仍是 0-dim tensor
- 现有 `logvars` clamp `[-4, 4]` 保持代码现状，不在本轮改区间
- 原文档 §6.1 中 clinic 展平维度写作 `n_c * 768`，应为 `n_c * 512`，文档一并修正；实现已按 `clinic_num_tokens * clinic_embedding_dim` 计算，不需要再改公式
- 返回值仍是 dict。新增 `counts` 三个整数，供 epoch 监控；不要把 `forward` 改成返回 tuple，以免现有 `cached["recon_losses"]["total"]` 断掉。实现上把 counts 放进同一个 dict 的 `counts_*` 键，或另缓存 `recon_counts`

B+single 构造 `ReconstructionLoss` 时，`dims["wsi"]` 改为 `K * 768`（默认 16*768），不要沿用 768。

## 2. 六个独立模型

六个候选不再压成 2×2 文档结构。命令行各注册一个 `--modality` 名字，类放在 `models/ablation_models/`，共享头和 helper 放在 `models/model_utils.py`。

| modality | 基座 | 读出 | 关键差异 |
|---|---|---|---|
| `survtri_poe_vae_b_single` | B 冻结 | 单头 | stage1 重建 `wsi_tokens`；stage2 真值保留、缺失回填后二次编码 |
| `survtri_poe_vae_b_multi` | B 冻结 | 7 头 | 一次编码、七次读出；无回填 |
| `survtri_poe_vae_b_film` | B 冻结 | FiLM | 与 B+multi 同一训练循环 |
| `survtri_poe_vae_c_single` | C 联合 | 单头 | 掩码修正后的现有 Model_C |
| `survtri_poe_vae_c_multi` | C 联合 | 7 头 | VAE 的 PoE 走 `avail`，重建不看 `avail`；生存走 pattern 枚举 |
| `survtri_poe_vae_c_film` | C 联合 | FiLM | 与 C+multi 同一训练循环 |

第 1 节掩码修正对六个模型全部生效。B+single 额外改 WSI 重建目标与 stage2 前向。

现有 `survtri_poe_vae`、`survtri_poe_vae_b_kl`、`survtri_poe_vae_b_crossstage1`、`survtri_poe_vae_b_nopretrain` 不改名。后三个 ablation 继承掩码修正，但不接 multi/film/refill。现有 `survtri_poe_vae --poe_variant B/C` 继续作为旧单头路径；新实验用上面六个独立名字。

## 3. 读出层设计

当前 `fuse_fc` 是两层 MLP：

```
Linear(d_z, mmhid) → ReLU → Dropout(0.1)
→ Linear(mmhid, mmhid) → ReLU → Dropout(0.1)
classifier = Linear(mmhid, 1)
```

新头保持同一 `fuse_fc` 宽度和 dropout，不要改成单层。`d_z=128`，`mmhid=args.poe_mmhid`（默认 256），`label_dim=1`。

`pattern_id` 统一成 `(B,)` long。训练循环里如果拿到标量 `s`，先 `as_pattern_ids(s, batch_size, device)` 再送入 head。

### 3.1 `multi`：pattern-specific fuse_fc + 共享 classifier

Cox loss 是排序损失，对 risk 的平移与正缩放不变。7 个完全独立的 `fuse_fc + classifier` 不在同一尺度上，混合队列无法统一排序。因此只让 `fuse_fc` 按 pattern 分化，`classifier` 共享：

```python
class MultiPatternHead(nn.Module):
    def __init__(self, d_z=128, mmhid=256, dropout=0.1):
        super().__init__()
        self.fuse_fc = nn.ModuleDict({
            str(s): nn.Sequential(
                nn.Linear(d_z, mmhid), nn.ReLU(), nn.Dropout(dropout),
                nn.Linear(mmhid, mmhid), nn.ReLU(), nn.Dropout(dropout),
            ) for s in range(1, 8)
        })
        self.classifier = nn.Linear(mmhid, 1)

    def forward(self, mu_joint, pattern_id):
        pattern_id = as_pattern_ids(pattern_id, mu_joint.size(0), mu_joint.device)
        risk = mu_joint.new_zeros(mu_joint.size(0), 1)
        for s in pattern_id.unique().tolist():
            sel = pattern_id == int(s)
            fused = self.fuse_fc[str(int(s))](mu_joint[sel])
            risk[sel] = self.classifier(fused)
        return risk
```

`fuse_fc_S` 吸收各 pattern 下 `mu_joint` 的尺度与形变差异（PoE 中固定先验专家 τ0 造成的收缩即在此被吸收，故本轮不改动原文档 §3 的 τ0 与 α 归一化机制）。

batch 内 `pattern_id` 可能不同。按 unique pattern gather/scatter，不要假设一个 batch 只有一个 pattern。

### 3.2 `film`：availability 条件化的单头

```python
class FiLMHead(nn.Module):
    def __init__(self, d_z=128, mmhid=256, emb_dim=32, dropout=0.1):
        super().__init__()
        self.emb  = nn.Embedding(8, emb_dim)          # index 0 不使用
        self.film = nn.Linear(emb_dim, 2 * d_z)
        self.fuse_fc = nn.Sequential(
            nn.Linear(d_z, mmhid), nn.ReLU(), nn.Dropout(dropout),
            nn.Linear(mmhid, mmhid), nn.ReLU(), nn.Dropout(dropout),
        )
        self.classifier = nn.Linear(mmhid, 1)
        nn.init.zeros_(self.film.weight)
        nn.init.zeros_(self.film.bias)

    def forward(self, mu_joint, pattern_id):
        pattern_id = as_pattern_ids(pattern_id, mu_joint.size(0), mu_joint.device)
        e = self.emb(pattern_id)
        gamma, beta = self.film(e).chunk(2, dim=-1)
        z = (1.0 + gamma) * mu_joint + beta           # 残差式，初始接近恒等
        return self.classifier(self.fuse_fc(z))
```

初始化：`film` 层权重和 bias 置 0，使起点接近恒等；`classifier` 用现有默认初始化。相对 `multi`：risk 尺度天然统一，pattern 间参数共享；代价是表达力略弱。

### 3.3 训练循环：一次编码、七次读出

Encoder 是唯一昂贵的部分，PoE 与 head 都很便宜。因此不训练 7 次，而是一次编码、七次读出：

```python
mu_list, logvar_list = encoder_forward(batch)      # 每 step 只跑一次

loss_surv = 0.0
for s in PATTERNS:                                  # 1..7
    pm  = pattern_to_mask(s)                        # (3,) bool
    sel = (avail_real >= pm).all(dim=1)
    if sel.sum() < min_batch_for_cox:               # 固定 8
        continue
    mask_s = pm.expand_as(avail_real)[sel]
    mu_s, logvar_s = poe(
        [mu[sel] for mu in mu_list],
        [lv[sel] for lv in logvar_list],
        mask_s,
    )
    risk_s = head(mu_s, pattern_id=s)
    loss_surv = loss_surv + w_s * cox_surv(risk_s, event_time[sel], censor[sel])
```

PoE 现有接口是 `mus: List[Tensor]` / `logvars: List[Tensor]`，不要改成 dict 再硬接。`avail_real` 在 complete-split 上为全 1，与当前 step 模拟缺失的 `avail` 无关；七个 pattern 都能被枚举，真正限制来自当前 batch 过滤后的样本量。

约束：

- `w_s = 1/7`，本轮不按真实缺失分布加权
- `min_batch_for_cox = 8`，样本过少的 pattern 本 step 跳过
- 不缓存 `(mu_i, logvar_i)`

`single` 读出模式下该循环退化为单次调用，pattern 来自 `avail`，不做枚举。B+single stage2 的二次编码见 §4.1，不走这套七次读出。

该循环抽为共享函数，供 B stage2 与 C 复用：

```python
def multi_pattern_surv_step(mu_list, logvar_list, avail_real,
                            poe, head, event_time, censor,
                            pattern_weights, min_batch_for_cox=8):
    ...
```

返回 `loss_surv`、各 pattern 的 risk、以及实际参与的 pattern 计数，供日志使用。若 7 个 pattern 全部因 batch 过小被跳过，该 step 的 survival loss 视为 0，但必须打 warning；C 模型仍保留 `L_rec + βJ`。

Cox 的 `event_time` / `censor` 与现有 `CoxSurvLoss` 接口保持一致。当前 POE 路径已强制 `bag_loss='cox_surv'`，本轮六个新模型同样只支持 Cox。

### 3.4 推理

```
pattern_id = bits_to_id(avail)           # 按样本，(B,) long
mu_joint   = PoE(可用模态)               # 不采样
risk       = head(mu_joint, pattern_id)
```

`single` 模式忽略 `pattern_id`。B+single 推理与训练 stage2 相同：先回填再二次编码，再走单头。该类应覆盖 `forward()`，让现有 `_summary()` 自动走 refill，不要只在 train loop 里特殊分支。

验证/测试 loader 当前 `batch_size=1`。multi/film 的 checkpoint 选择需要 7-pattern 加权 c-index，必须在 val 上按病人收集各 pattern 的 risk：每个病人 encoder 一次，再对 7 个 pattern 做 PoE+head。不能依赖训练 batch 内的 pattern 枚举，也不要把 val loader 改成大 batch。

## 4. 训练流程（改写原文档 §8）

B 模型继续走现有两阶段 trainer（`POE_MODALITIES` + `poe_variant='B'`）。C 模型继续走单循环联合训练。`bag_loss` 仍只支持 `cox_surv`。

六个新名字都加入 `POE_MODALITIES` 和 `POE_ALL_MODALITIES`，与现有 `survtri_poe_vae` 一样。两阶段只由 `poe_variant in {"A", "B"}` 触发，**不要**把 C 三个名字排除出 `POE_MODALITIES`：现有 `_train_loop_survival()` 用 `modality in POE_MODALITIES` 计算 β warmup，C 一旦不在这个集合里，`combine_loss(..., beta=None)` 会坏掉。

加载 stage1 ckpt 的时机保持现状：`_train_val_test()` 先跑 stage1，再 `torch.load` stage1 ckpt，再冻结 / `set_training_stage("stage2")`，再 `_init_optim()`。新 B 模型必须把 `freeze_backbone_keep_head()` 放在创建 optimizer 之前。现有 B 路径只调 `set_training_stage("stage2")`，不会冻结；新 B 路径要在这个位置额外冻结。

### 4.1 `survtri_poe_vae_b_single`

这是六个模型里唯一改 WSI 重建目标和二次编码的分支。

**Stage 1**

- 损失仍是 `L = L_rec + β(t) * J`
- 掩码语义按 §1
- **WSI 重建目标改为 MIL Resampler 输出的 `wsi_tokens (B, K, 768)`**，不再调用 `WSITargetPoolingHead`
- `decoder_wsi` 用现有 `ModalityDecoder(latent_dim, hidden, K*768)`，输出 `(B, K*768)`。`ReconstructionLoss` 在 flatten 后与 `wsi_tokens.reshape(B, -1)` 对齐。送回 encoder 前再 reshape 成 `(B, K, 768)`
- `K = wsi_resampler_tokens`，默认 16
- gene / clinic 重建目标不变：`x_omic` flatten 为 `(B, 4*768)`，`x_clinic` flatten 为 `(B, n_c*512)`
- 该 stage1 checkpoint 与现有 pooled-WSI 的 B checkpoint **不互换**。stage1 cache tag 已包含 `args.modality`，不必再改 cache 公式

**Stage 2**

加载 stage1 ckpt 后、创建 optimizer 前，调用新的冻结接口（不要复用 Model A 的 `freeze_backbone_for_probe()`，那个会把 `fuse_fc/classifier` 一起冻掉）：

```
freeze:
  wsi_resampler, wsi_encoder, gene_encoder, clinic_encoder,
  poe, decoder_wsi, decoder_gene, decoder_clinic,
  reconstruction_loss, linear_probe
  （若该类仍构造了 wsi_target_head，一并冻结且 stage2 不使用）
train:
  fuse_fc, classifier
```

冻结模块 `eval() + requires_grad_(False)`。

当前基类 `train()` 在 `backbone_frozen=True` 时会把 `fuse_fc/classifier` 也打成 eval，这是 Model A 探针路径的行为。不能直接改掉，否则 A 回归。处理方式：

- `freeze_backbone_for_probe()` 继续设 `backbone_frozen=True`，`head_trainable=False`
- `freeze_backbone_keep_head()` 设 `backbone_frozen=True`，`head_trainable=True`
- `train(mode)`：冻结模块恒 eval；若 `head_trainable` 则 `fuse_fc/classifier` 跟随 `mode`，否则保持 eval；`linear_probe` 仍跟随 `mode`（仅 A 使用）

`_init_optim()` 对这三个 B 新模型关闭 grouped LR。现有判定是 `poe_variant == "B" and hasattr(model, "get_stage2_param_groups")`，新 B 类会继承这个方法，必须再排除 `survtri_poe_vae_b_single/multi/film`。冻结后若仍走 grouped LR，encoder 组为空会报错或静默只拿到 head 组，行为不稳定。改为 `filter(lambda p: p.requires_grad, model.parameters())`，只优化 head。

**Stage 2 前向（真值保留，只填缺失）：**

```
pass1:
  对 avail=1 的模态正常编码
  缺失模态仍把占位 tensor 送进 encoder（现有代码已如此），但 PoE 只用 avail
  decode 出 recon_wsi, recon_gene, recon_clinic
  本阶段用 mu_joint 解码，不采样

refill:
  wsi_tokens_2    = avail[wsi]    ? wsi_tokens_real    : recon_wsi.view(B, K, 768)
  gene_tokens_2   = avail[gene]   ? x_omic_real        : recon_gene.view(B, 4, 768)
  clinic_tokens_2 = avail[clinic] ? x_clinic_real      : recon_clinic.view(B, n_c, 512)

pass2:
  若三个模态原本都在，跳过二次编码，直接用 pass1 的 mu_joint
  否则：
    重建得到的 WSI tokens 直接进 wsi_encoder，不再二次经过 resampler
    三路 encoder 再跑一遍
    PoE 使用全 1 mask
    取 mu_joint（不采样）送入单头
```

observed 的 gene/clinic/WSI tokens 不得被 recon 替换。`x_omic_real` / `x_clinic_real` 用 `_reshape_gene` / `_reshape_clinic` 后的 token 形状。

Stage2 仍计算 `L_rec/J` 仅供日志；`combine_loss()` 对 B 仍只返回 survival loss，梯度不得回到冻结模块。日志用的重建应对 refill 前的 pass1 结果，不要用二次编码后的 joint 再解码一遍。pass2 必须 `torch.no_grad()`，或依赖冻结参数；推荐 `no_grad`，避免误接到未冻模块。

### 4.2 `survtri_poe_vae_b_multi` / `survtri_poe_vae_b_film`

**Stage 1**

- 与掩码修正后的默认 B 相同
- WSI 仍用原文档 §2.3 的独立池化头，decoder_wsi 仍输出 `(B, 768)`

**Stage 2**

- 冻结集合与 §4.1 相同（enc/resampler/PoE/dec），只训对应 head（`MultiPatternHead` 或 `FiLMHead`）
- 无回填，无二次编码
- 按 §3.3 一次编码、七次读出
- grouped LR 关闭，同 §4.1
- val 不走普通 `val_cindex`。在 `_step()` / `_summary()` 旁加 7-pattern 评估：每个 val 样本 encoder 一次，枚举 7 个 pattern，按 §6.2 用 `val/cindex_weighted` 选 ckpt

### 4.3 `survtri_poe_vae_c_single`

流程同原文档 §8.4 / 现有 Model_C，掩码语义按 §1 修正。无回填，无 pattern 枚举。WSI 仍走池化头。β 仍走 `_get_poe_beta()`。

### 4.4 `survtri_poe_vae_c_multi` / `survtri_poe_vae_c_film`

联合训练，Encoder 每 step 只跑一遍：

```
L = L_rec + β(t) * J + λ * Σ_s w_s * L_surv,s
```

- `L_rec` 不看 `avail`；`J` 与 PoE 走当前 step 的 `avail`
- survival 走 §3.3 的 pattern 枚举，与当前 step 的 dropout mask 独立
- 无回填
- Encoder 会同时收到 7 个 pattern 的 survival 梯度
- β 必须仍由 `_get_poe_beta()` 提供，因此这两个名字也要在 `POE_MODALITIES` 里
- val / ckpt 与 §4.2 相同，按 `val/cindex_weighted` 保存

`combine_loss()` 对 C 仍是 `vae_loss + λ * survival_loss`；multi/film 把枚举后的加权 Cox 作为这里的 `survival_loss`。`_train_loop_survival()` 里现有 `survival_loss = loss_fn(...); loss = model.combine_loss(survival_loss, beta=beta)` 对 multi/film 不够用，因为一次 forward 无法表达七次 Cox。实现上让 C+multi/film 的 `forward()` 只做 encoder+VAE，再在 train loop 或 `model.survival_loss_from_cached()` 里调 `multi_pattern_surv_step`。不要为了省事把七次 Cox 藏进 `forward()` 再只返回其中一个 risk——日志里的 train c-index 对 multi/film 可以只记 pattern=PGC 的 risk，ckpt 仍看 val weighted。

Helper 约定：

```python
PATTERNS = (1, 2, 3, 4, 5, 6, 7)

def pattern_to_mask(pattern_id, device=None, dtype=torch.bool):
    # bit0=wsi, bit1=gene, bit2=clinic → (3,) bool
    pid = int(pattern_id)
    bits = [(pid >> 0) & 1, (pid >> 1) & 1, (pid >> 2) & 1]
    return torch.tensor(bits, dtype=dtype, device=device)

def bits_to_id(avail_mask):
    # avail_mask: (B, 3) bool → (B,) long in 1..7
    bits = avail_mask.to(dtype=torch.long)
    return bits[:, 0] + 2 * bits[:, 1] + 4 * bits[:, 2]
```

## 6. 监控与模型选择（增补原文档 §11）

### 6.1 Stage 1 / VAE 部分

- `count/rec_wsi` / `count/rec_gene` / `count/rec_clinic`：每 epoch 参与重建的样本数。掩码修正后应接近 batch 全量，而不是模拟缺失 `avail` 的计数
- `loss/rec_*` 按 count 做 epoch 平均，`NaN` 跳过；step 日志若拿到 nan tensor，跳过该键，不要 `float(nan)` 污染 wandb
- 掩码修正后 `loss/rec_*` 绝对值会上升（多了跨模态生成的困难样本），属预期行为

### 6.2 生存部分

单头模型（B+single / C+single）：

- 继续用现有全模态 `val_cindex`（内部 PGC，现有 eval 标签 PCG）
- `save_best_from_epoch` 默认仍从 epoch 10 开始
- 若打开 `--eval_modalities all`，额外记录 7 个 subset，但不改 best ckpt 准则
- B+single 的 val/test 必须走 refill `forward()`，不能只用 pass1 的残缺 PoE

multi / film：

- 在 val 上对每个病人枚举 7 个 pattern，记录：
  - `val/cindex_P`、`val/cindex_G`、`val/cindex_C`
  - `val/cindex_PG`、`val/cindex_PC`、`val/cindex_GC`
  - `val/cindex_PGC`
  - `val/cindex_weighted` = 均匀平均（跳过无法计算的 pattern）
  - `val/cindex_worst` = 7 个中的最小值
- **best checkpoint 按 `val/cindex_weighted` 保存**
- 现有 `--eval_modalities` 作为独立的 test-time 7-subset 开关，不替代上面的训练期 pattern 指标
- 对外写 csv / Table2 时，`val/cindex_PGC` 对应列名 `PCG`，`val/cindex_GC` 对应列名 `CG`
- 某个 pattern 的 val 事件数不足、c-index 算不出来时，该 pattern 记 `NaN` 并从 weighted / worst 中跳过；若 7 个全失败，本 epoch 不更新 best ckpt

## 7. 测试与验收

实现时至少覆盖：

1. complete-split 单元：`avail` 可关掉某一模态，该模态仍进入 `L_rec`（重建不看 `avail`）
2. B+single refill：observed tensor 不变；只替换缺失槽；三模态都在时跳过二次编码；缺失 WSI 使用 reshape 后的 `(B, K, 768)` decoded tokens，且不经过第二次 resampler
3. B+single 重建形状：`ReconstructionLoss` 对 `(B, K*768)` 与 `(B, K, 768)` 都能 flatten 成逐样本标量，不会留下 `(B, 768)` 的半平均
4. pattern helper：P/G/C/PG/PC/GC/PGC 的 id/mask 往返；Cox 在 pattern batch `< 8` 时跳过
5. 冻结：B+single/multi/film 的 stage2 中 enc/PoE/dec `requires_grad=False`，head 为 `True`；`model.train()` 后 head 仍处于 training，冻结模块处于 eval。Model A 的 `freeze_backbone_for_probe()` 后 `fuse_fc/classifier` 仍为 eval
6. C 接线：三个 C 名字在 `POE_MODALITIES` 内，`_get_poe_beta()` 返回数值而不是 `None`
7. smoke：B+single 与 C+multi 各对一个含模拟缺失的 tiny complete batch 做一次 forward
8. 回归：现有 `survtri_poe_vae` 命令仍可启动，且重建不再被模拟缺失的 `avail` 挡住
